# 企业知识中心部署手册

本文说明如何把企业知识中心部署到本地开发环境或生产环境。产品定位、页面操作与 Agent 接入见 [使用手册](使用手册.md)。

## 1. 适用对象与范围

本手册面向运维、实施与后端开发人员，覆盖：

- 运行所需软件与配置
- 本地开发启动
- Docker 一键部署（MySQL + API + Nginx）
- 数据库迁移、管理员初始化、升级与备份
- 生产环境安全检查

不包含业务操作步骤；员工与智能体用法见 [使用手册](使用手册.md)。

## 2. 系统组成

本仓库为 Monorepo：

| 组件 | 目录 | 说明 |
| --- | --- | --- |
| Web | `apps/web` | Vue 3 前端，员工阅读、编辑、检索与签发 Agent |
| API | `apps/server` | FastAPI，知识、权限、版本、附件、审计、Agent 只读接口 |
| 数据库 | MySQL 8 | 默认库名 `knowledge_center`，字符集 utf8mb4 |
| 附件存储 | `UPLOAD_DIR` | 本地目录；生产环境必须显式配置 |
| 反向代理 | Nginx（Docker `web` 服务） | 对外提供 80 端口，将 `/api/` 转到 API |

人和智能体共用同一套数据与权限。关闭 LLM / Embedding / RAG 后，创建、浏览、搜索、权限、版本仍可用。

## 3. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows / Linux / macOS |
| Python | 3.11 或以上 |
| Node.js | 18 或以上，含 npm |
| Docker | 本地 MySQL 或完整容器部署时需要 Docker Desktop / Docker Engine |
| 磁盘 | 预留数据库与附件空间；附件默认单文件上限 50 MB（可在系统配置中调整） |

生产环境建议在反向代理后启用 HTTPS，并将 `CORS_ORIGINS` 限制为实际前端来源。

## 4. 配置项

在项目根目录复制模板：

```powershell
Copy-Item .env.example .env
```

| 变量 | 说明 | 备注 |
| --- | --- | --- |
| `DATABASE_URL` | SQLAlchemy 连接串 | 本地示例：`mysql+pymysql://admin:password@localhost:3306/knowledge_center?charset=utf8mb4` |
| `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD` / `MYSQL_DATABASE` | Compose 中 MySQL 初始化账号 | 与 `DATABASE_URL` 保持一致 |
| `MYSQL_PORT` | 宿主机映射的 MySQL 端口 | 默认 3306；占用时可改为 3307，并同步改 `DATABASE_URL` |
| `ENVIRONMENT` | `development` / `test` / `production` | 生产必须为 `production` 或 `prod` |
| `SECRET_KEY` | JWT 签名密钥 | 生产至少 32 字符，禁止示例值或 `replace-with-` 前缀 |
| `UPLOAD_DIR` | 附件物理目录 | 生产必须设置；开发未设置时默认 `apps/server/uploads` |
| `MAX_UPLOAD_SIZE_MB` | 环境变量中的默认上传上限 | 管理员在「存储配置」中保存的值会覆盖运行时上限 |
| `CORS_ORIGINS` | 允许的前端来源，逗号分隔 | 开发常用 `http://localhost:3000`；Docker 全栈常用 `http://localhost` |
| `VITE_API_BASE_URL` | 前端 API 前缀 | 一般为 `/api/v1` |
| `VITE_API_PROXY_TARGET` | Vite 开发代理目标 | 一般为 `http://localhost:8000` |
| `MCP_API_KEY` | MCP 进程使用的 Agent Key | 以 `kck_` 开头，优先于 `MCP_AUTH_USER` |
| `MCP_AUTH_USER` | MCP 回退使用的系统用户 | 禁止静默回落到管理员 |
| `WEB_PORT` | Compose 中 Nginx 对外端口 | 默认 80 |

不要把 `.env`、密钥、数据库密码或上传文件提交到 Git。

## 5. 本地开发部署

### 5.1 启动数据库

```powershell
docker compose up -d db
```

仅启动 MySQL，不构建 API / 前端镜像。等待容器 healthy 后再做迁移。

### 5.2 后端

```powershell
Set-Location apps/server
python -m pip install -r requirements.txt
python -m alembic upgrade head
python init_admin.py --username admin --password "请替换为强密码"
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

说明：

- 依赖版本已锁定在 `apps/server/requirements.txt`。
- 结构变更一律使用 Alembic，不要在生产执行 `python db_init.py`（`ENVIRONMENT=production` 时该脚本会拒绝运行）。
- `init_admin.py` 用于首次创建或重置管理员；公开注册只能创建普通用户（`viewer`）。
- 新密码最少 8 位。已有短密码账号仍可登录，但重置时应改为强密码。

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:8000/docs | Swagger |
| http://127.0.0.1:8000/redoc | ReDoc |
| `GET /health` | 进程存活 |
| `GET /ready` | 数据库可查询时才成功 |

### 5.3 前端

新开终端：

```powershell
Set-Location apps/web
npm install
npm run dev
```

浏览器打开 http://localhost:3000 。开发环境由 Vite 把 `/api` 代理到后端，无需在业务代码中写死后端地址。

### 5.4 Windows 一键启动

根目录 `start.bat` 会：

1. `docker compose up -d db`
2. 启动后端 8000
3. 启动前端 3000

`stop.bat` 关闭前后端进程并 `docker compose stop db`（数据卷保留）。**首次**仍需先完成迁移与 `init_admin.py`。

## 6. Docker 完整部署

用于把数据库、API、Nginx 一起拉起。API 与 Web 使用 Compose profile `full`，不会影响「只起 MySQL」的本地开发。

```powershell
Copy-Item .env.example .env
# 编辑 .env：设置至少 32 位随机 SECRET_KEY、强数据库密码、CORS_ORIGINS、ENVIRONMENT=production
$env:SECRET_KEY = "至少32字符的随机密钥"
docker compose --profile full up -d --build
```

行为说明：

- `db`：MySQL 8，启用 ngram（中文 FULLTEXT），数据卷 `mysql_data`
- `api`：执行 `alembic upgrade head` 后启动 Uvicorn；附件目录挂载为 `/data/uploads`（卷 `uploads_data`）
- `web`：构建前端静态资源，Nginx 监听 80，`/api/` 反代到 `api:8000`

访问：

- 员工界面：http://localhost/ （或 `WEB_PORT`）
- 健康检查：http://localhost/health
- 就绪检查：http://localhost/ready

生产环境必须设置真实 `SECRET_KEY`。`ENVIRONMENT=production` 时缺少 `SECRET_KEY` 或 `UPLOAD_DIR`、或仍使用示例密钥，API 会拒绝启动。Compose 中 API 的 `UPLOAD_DIR` 已固定为 `/data/uploads`。

容器内 API 连接数据库使用主机名 `db`，不要再写 `localhost`。

停止：

```powershell
docker compose --profile full down
```

加 `-v` 会删除 MySQL 与附件卷，生产禁止误用。

## 7. 数据库迁移与初始化

查看当前头版本并升级：

```powershell
Set-Location apps/server
python -m alembic heads
python -m alembic upgrade head
```

正式库执行迁移前先备份。Docker `api` 容器启动时会自动 `upgrade head`；手工部署必须在启动 Uvicorn 前执行。

创建管理员：

```powershell
python init_admin.py --username admin --password "请替换为强密码"
```

该命令会创建账号，或将已有同名用户提升为管理员并重设密码。重设密码会使该用户已签发的 JWT 立即失效。

## 8. 升级步骤

1. 备份数据库与 `UPLOAD_DIR` / `uploads_data` 卷。
2. 拉取新版本代码。
3. 后端：`python -m pip install -r requirements.txt`，再 `python -m alembic upgrade head`。
4. 前端：`npm ci` 后 `npm run build`（或重新 `docker compose --profile full up -d --build`）。
5. 检查 `GET /health`、`GET /ready`，并用管理员账号登录验证空间列表与检索。

GitHub Actions（`.github/workflows/ci.yml`）在 push / PR 时会跑 `pytest` 与前端 `npm run build`，不能替代目标环境的真实 MySQL 迁移验证。

## 9. 备份与恢复

至少备份两处：

1. **MySQL**：`mysqldump` 或卷 `mysql_data` 的快照。
2. **附件**：`UPLOAD_DIR` 目录或 Docker 卷 `uploads_data`。数据库中的附件记录与物理文件必须一起恢复，否则会出现「物理文件丢失」。

恢复后执行 `alembic upgrade head`（若备份来自旧版本），再启动服务。

## 10. 生产安全清单

- [ ] `ENVIRONMENT=production`
- [ ] `SECRET_KEY` 为随机长密钥，不是仓库示例值
- [ ] `UPLOAD_DIR` 指向独立、可写、已纳入备份的目录
- [ ] 数据库账号使用强密码，勿对公网暴露 3306
- [ ] `CORS_ORIGINS` 仅包含实际前端来源
- [ ] 对外 HTTPS；Nginx 或上游网关限制上传体积
- [ ] 管理员密码不少于 8 位，且不要使用弱口令
- [ ] Agent 只使用 `kck_` Key，不要把员工密码配给智能体
- [ ] 确认登录失败限流、改密后旧 Token 失效、附件扩展名白名单已启用

管理员可在 **配置中心 → 存储配置** 调整单文件大小与允许的扩展名；路径本身仍由 `UPLOAD_DIR` 决定，界面不可改，以避免路径穿越。HTML / HTM 等类型会强制以附件下载，不会在浏览器中直接打开。

## 11. 验证

本地或 CI：

```powershell
Set-Location apps/server
python -m pytest -q

Set-Location ..\web
npm run build
```

后端测试使用隔离 SQLite 与临时附件目录，**不会**写入业务 MySQL。

## 12. 常见问题

**无法连接数据库**

检查容器是否 healthy，以及 `.env` 中主机端口是否与 `MYSQL_PORT` / Compose 映射一致。本机 3306 被占用时改为 `3307:3306` 并同步 `DATABASE_URL`。

**生产启动失败，提示必须设置 SECRET_KEY / UPLOAD_DIR**

这是预期保护。补全环境变量后重启，不要把开发默认值带进生产。

**Docker 全栈启动后页面空白或接口跨域失败**

将 `CORS_ORIGINS` 设为浏览器实际来源（如 `http://localhost` 或公司域名），并确认是通过 Nginx 的 80 端口访问，而不是直连 API 8000。

**登录后立刻回到登录页**

后端或数据库未就绪时，前端代理 `ECONNREFUSED` 会表现为登录失败。先访问 `/health` 与 `/ready`。

**MCP 起不来**

设置 `MCP_API_KEY`（推荐）或 `MCP_AUTH_USER`。两者都缺时进程拒绝以管理员身份回落启动。
